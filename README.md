## 🚀 Why This Exists

The Roblox ecosystem moves fast. Official documentation, engine behavior, and best practices shift between releases like sand dunes in a desert wind. Most toolkits you find online were written two engine versions ago, carry deprecated API calls, and quietly break your game in production.

**RoBlocks Studio Toolkit** was born from a simple frustration: *why do developers and AI agents keep repeating the same outdated Luau patterns?*

We built a repository that is:

- **Grounded in official Roblox documentation** — every script, every helper, every pattern is cross-referenced against the canonical sources.
- **Opinionated by design** — we don't hand you ten ways to do something; we hand you the one that survives contact with a live player base.
- **Agent-ready** — structured so that autonomous coding assistants can ingest, reason about, and generate production-grade Luau without drifting into hallucinated APIs.
- **Actively curated** — stale snippets get pruned, not archived. This is a living organism, not a museum.

Whether you are a solo scripter building your first obby or a studio coordinating a dozen contributors, this toolkit aims to be the quiet engine room beneath your workflow.

## 🧭 How It Works (In Plain English)

Imagine a library where every book rewrites itself when the laws of physics change. That's the mental model here.

1. **You (or your AI agent) request a capability** — say, a data persistence helper, a tween scheduler, or a network event wrapper.
2. **The toolkit surfaces the current-best pattern**, annotated with the reasoning and the official reference.
3. **You drop it into your project** and extend it. No vendor lock-in, no runtime dependency on a remote service.
4. **When Roblox evolves**, the maintainers revisit the pattern, and if it's outdated it gets rewritten — not patched with duct tape.

This is less a "framework" and more a **living reference implementation** that happens to be copy-paste friendly.

## 🧱 Core Modules

- **`/core/state`** — Predictable state management that plays nicely with replication.
- **`/core/networking`** — Remote event and function wrappers with type safety and rate-limit guards.
- **`/core/persistence`** — DataStore abstractions that fail gracefully and log meaningfully.
- **`/ui/responsive`** — Layout primitives that scale across device classes.
- **`/ui/i18n`** — Localization helpers with runtime language switching.
- **`/tooling/lint`** — Static analysis rules tailored to modern Luau.
- **`/tooling/agents`** — Manifests and prompts designed for autonomous coding assistants.

Each module ships with:
- A short "why this exists" note
- A usage example grounded in a realistic scenario
- A list of upstream documentation references
- A deprecation watchlist entry

## ❓ Frequently Asked Questions

**Q: Is this a framework I have to adopt wholesale?**  
A: No. Every module stands alone. Adopt one helper or all of them — your call.

**Q: Will this work with my existing codebase?**  
A: Yes. The toolkit is designed to be incrementally adoptable. Start with a single utility and grow from there.

**Q: Do I need an AI agent to use this?**  
A: Not at all. The agent-facing structure is a bonus, not a requirement.

**Q: How often is content refreshed?**  
A: Maintenance happens continuously, with a formal review each Roblox engine release cycle.

**Q: Can I contribute?**  
A: Contributions are welcome, provided they are grounded in official documentation and include a rationale.
